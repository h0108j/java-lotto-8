## 💎 프로그램 소개

사용자에게 구입 금액을 입력받아 로또를 자동으로 발행하고,  
당첨 번호와 비교하여 결과 및 총 수익률을 계산하는 콘솔 기반 로또 발매기입니다.

---

## ⚙️ 기능 목록

### 1️⃣ 구입 금액 입력

- [x] 로또 구입 금액 입력

  - `구입금액을 입력해 주세요.` 출력
  - 유효성 검사 실패 시 예외 발생
    - 입력 값이 숫자가 아닌 경우
    - `1,000`원 미만이거나 나누어 `1,000`원으로 나누어 떨어지지 않는 경우
    - 최대 구매 가격을 초과한 경우 (최대 구매 가격은 구현 과정에서 결정)
  - 유요한 입력이 있을 때까지 반복

>🛑 예외 발생 시 각 상횡에 맞게 `[ERROR]`로 시작하는 예외 메시지 출력

---

### 2️⃣ 로또 발행

- [x] 한 장당 `1,000`원 기준으로 입력 금액에 맞는 구매 개수 계산
- [x] 구매 개수에 맞게 로또 번호를 생성
  - 각 로또당 1~45 사이의 번호 중복 없이 6개 생성
  - 값 생성 시 `pickUniqueNumbersInRange()`를 통해 랜덤 값 추출
  - 각 로또 번호를 오름차순으로 정렬
- [x] 구매 개수와 각 로또 번호 출력
  - 출력 양식:
    ```
    3개를 구매했습니다.
    [8, 21, 23, 41, 42, 43]
    [3, 5, 11, 16, 32, 38]
    [7, 11, 16, 35, 36, 44]
    ```

---

### 3️⃣ 당첨 번호 입력

- [x] `당첨 번호를 입력해 주세요.` 출력
- [x] 당첨 번호 6개 입력
    - 번호는 쉼표(`,`)로 구분
    - 유효성 검사 실패 시 예외 발생
      - 쉼표(`,`) 외의 문자가 입력된 경우
      - `1~45` 범위에 벗어나는 값이 있는 경우
      - 중복 값이 있는 경우
    - 유요한 입력이 있을 때까지 반복
- [x] `보너스 번호를 입력해 주세요.` 출력
- [x] 보너스 번호 1개 입력
  - 유효성 검사 실패 시 예외 발생
    - 숫자가 아닌 경우
    - 당첨 번호와 중복되는 경우
    - `1~45` 범위에서 값이 벗어나는 경우
  - 유요한 입력이 있을 때까지 반복

>🛑 예외 발생 시 각 상횡에 맞게 `[ERROR]`로 시작하는 예외 메시지 출력

---

### 4️⃣ 당첨 결과 계산

- [x] 입력받은 당첨 번호 및 보너스 번호를 각 로또 생성 번호와 비교
- [x] 일치한 개수에 따라 아래 기준으로 등수 계산

| 등수 | 조건 | 상금 |
|------|------|------|
| 1등 | 6개 번호 일치 | 2,000,000,000원 |
| 2등 | 5개 + 보너스 번호 일치 | 30,000,000원 |
| 3등 | 5개 번호 일치 | 1,500,000원 |
| 4등 | 4개 번호 일치 | 50,000원 |
| 5등 | 3개 번호 일치 | 5,000원 |

- [x] 각 등수별 당첨 내역 출력
  - 출력 양식:
    ```
    3개 일치 (5,000원) - 1개
    4개 일치 (50,000원) - 0개
    5개 일치 (1,500,000원) - 0개
    5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
    6개 일치 (2,000,000,000원) - 0개
    ```

---

### 5️⃣ 수익률 계산 및 출력

- [x] 전체 상금을 합산하고 수익률 계산
  - `(총 상금 / 구입 금액) × 100`
- [x] 소수점 둘째 자리에서 반올림하여 수익률 출력
  - 출력 양식: `총 수익률은 62.5%입니다.`

## 🧠 설계 포인트

- MVC 패턴 기반으로 `Controller`, `View`, `Domain의` 역할을 명확히 분리했습니다.
- `Lotto`와 `Lottos` 생성시에 팩토리 패턴을 사용하여, 검증 및 생성의 책임을 분리했습니다.
- `NumberGenerator`인터페이스를 정의하여 `LottoFactory`에서 로또 생성 방법을 유연하게 변경하고 랜덤 로직도 예측 가능하게 테스트 할 수 있도록 전략 패턴을 구현했습니다.
- `LottoRank` Enum에 등수별 당첨 조건과 상금을 정의하여, 조건 변경 시에도 단일 수정으로 일관성을 유지할 수 있도록 했습니다.
- `DTO`를 사용해 `View`가 `Domain` 객체를 직접 참조하지 않도록 분리하고, `Service` 계층을 통해 변환 책임을 위임했습니다.
